# 环境、构建与部署

## 电脑重建

Windows x64 / Linux AArch64；建议独立 Python 环境。依赖见根 requirements.txt，开发测试依赖见 requirements-dev.txt。ARM CPython 3.7 参考锁见 07 目录；本工程不包含 wheelhouse，不能直接照搬历史离线安装命令。Python Tkinter 由 Python/Tcl-Tk 发行版提供。

优先使用根目录 tools/run_reconstruction.py。工程含 Windows 和 AArch64 原生求解器及 Windows 运行 DLL，不含 Linux x86_64 原生二进制。数值选项保持 C++17、FP64、`-ffp-contract=off -fno-fast-math`，不要开启快速数学重排。

## FPGA 工程重建

工具：AMD Vivado / Vitis HLS 2025.2；器件 `xczu9eg-ffvb1156-2-i`。先复制 `project/releases/performance` 到独立 ASCII 构建目录，创建 bin、reports 目录；不要直接覆盖冻结发布文件。

硬件参数以 `hardware_evidence/parameters.json` 为准：150 MHz、周期 6.666666666666667 ns、burst 128、outstanding 8、AXI 请求宽度 128。

设置环境变量 PS_CLOCK_MHZ=150、PS_HLS_PERIOD=6.666666666666667、PS_AXI_BURST=128、PS_AXI_OUTSTANDING=8、PS_AXI_WIDTH=128 后，依次执行：

1. Vitis HLS 执行 `scripts/hls.tcl`，生成 full_gemv IP。
2. Vivado batch 执行 `scripts/build_bd.tcl`，重建 PS、AXI、reset、full_gemv、风扇与约束。
3. Vivado batch 执行 `scripts/direct_build.tcl`，综合、布局布线、时序检查并导出 bit/XSA。

两个 Vivado Tcl 中的 XilinxTclStore 安装目录及部分历史脚本里的 D:/ 工具路径须按本机替换。脚本保留原版本，不将本机路径写成通用安装地址。

软件重建入口 `scripts/build_m4_software.py --host <g++路径> --arm <交叉g++路径>`，执行前创建 reports/bin；其输出与新生成位流必须重新形成匹配发布配置，不能替换文件后继续使用旧哈希。

## 板端与显示

板端部署入口及硬件绑定检查见 `project/releases/performance/scripts/run_target.py`、`hardware_profile.py` 和 configs；它们会访问 FPGA/寄存器，只在正确板卡和匹配位流下使用。相机需厂家驱动/SDK及对应系统库，本包保留接口实现，不再分发厂家安装器。

独立电脑演示入口为 `05_控制与显示程序/paper_live_demo/start.cmd`，部署脚本 deploy.py 需要 PowerShell 串口接口。该演示左侧为相机实时预览，右侧为论文匹配数据经电脑 CPU 算法重建；呈现等待时间不是 FPGA 求解耗时。板端双栏程序在 project/repo/board/dual_display。
