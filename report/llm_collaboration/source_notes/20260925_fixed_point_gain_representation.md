# 定点增益表示：Q16.16 让 6/8 个候选归零，改用每量独立的 2 的幂指数

- 日期：2026-09-25
- 主题：定点增益表示（gain representation）
- 触发：方案 §6.3 位宽表 —— 数据默认 12 bit 右对齐进 16 bit 容器，增益用 Q16.16
- 结论：按原表示，定点层在真实 B 档模型上会输出全零；改成 2 的幂指数后误差压到量化地板

## 一、任务指令与触发条件

方案 §6.3 的位宽表规定：数据默认 **12 bit 右对齐进 16 bit 容器**，**增益用 Q16.16**
（小数点固定在低 16 位）。定点核的增益换算写在 `src/fpga/hls/ps_fixed.hpp`：

```cpp
inline int32_t scale_to_gain_q16(double scale) {          // Q16.16
    return (int32_t)sat_round_i64(scale * (double)(1 << 16), ...);
}
```

Q16.16 的最小分辨率是 `2^-16 = 1.53e-5`。这个分辨率是否够用，取决于增益本身的量级。

## 二、发现：Q16.16 把 6/8 个候选直接压成 0

在真实 B 档模型上量增益。B 档的 U/V 增益落在 **1e-6 量级**，其中 `u_scale ≈ 3.0e-6`。

| 项 | 数值 |
|---|---|
| `u_scale`（B 档） | ≈ 3.0e-6 |
| `round(scale · 2^16)` | **0** |
| 4 个候选 × {U, V} 中被取整到 0 的个数 | **6 / 8** |

`scale · 2^16 = 3.0e-6 × 65536 ≈ 0.20`，四舍五入即 0。增益被压成 0 之后，定点核的
乘累加整条为零，**整层输出全零模型**。这已不是个别候选的边界问题，而是 **Q16.16 这个
表示在 1e-6 量级上整体失效**。

## 三、修正：每量独立的 2 的幂指数

把 scale 从连续值改成 **2 的幂**：

- 旧：`scale = max|x| / 32767`（连续，写进 Q16.16 会被舍入）
- 新：`scale = 2^ceil(log2(max|x| / 32767))`（尾数恒为 1，增益可精确表示，相对误差为 0）

三个量（U / S / V）**各自带一个指数，不是共用一个共享指数**。不共享的理由：三个量的
scale 跨度大，共用一个指数会让最大的那个溢出，或让最小的那个多丢若干 bit 精度。每个量
独立带指数后，每个增益都精确；代价只有 `2^ceil` 相对连续值最多浪费一倍（即最多少用 1 bit
码字精度）。

## 四、实测结果

| 指标 | 旧 Q16.16 | 新 2 的幂指数 |
|---|---|---|
| 前向 `Bf` vs 双精度参考 | 输出全零（100%） | **0.005%（0.5 LSB）** |
| 伴随 `Bᵀr`（用伴随恒等式 `rᵀ(Bf) = (Bᵀr)ᵀf` 作判据） | — | **0.0091%** |

两侧都压到量化地板。伴随侧用恒等式而非手写参考：恒等式不依赖任何手写基准，前向既已验到
0.5 LSB，直接取它当基准。

## 五、自我纠错轨迹

1. **初判「个别候选取整到 0」，倾向加宽 MAC 累加器。**
   复查误差性质后否决：增益取整带来的是**相对误差**，与累加器位宽无关；要改的是增益的
   表示，不是累加器。若照初判去加宽累加器，问题会原样保留。
2. **伴随侧判据被自己改判。**
   初版把伴随侧的偏差判成「内核存在第二个缺陷」。改用伴随恒等式复算后，恒等式以 0.0091%
   成立 —— 伴随内核正确，**初版那份手写参考的算式约定与伴随方向不一致**。手写参考引入了
   自己的约定假设，恰好成了出错来源。结论：一个方向已有独立验证的基准时，优先用它构造
   恒等式，而不是再手写第二份参考。
3. **「磁盘字段有损失」这条误判也一并更正。** `psm_format.h` 的 `u_scale` / `s_scale` /
   `v_scale` 三个字段是 `float`，不是 Q16.16，写盘与读盘都不需要改。问题只出在从 `float`
   转成硬件增益那一步。

## 六、同源发现：不得先在定点域做 A 相减得到 A_d

同一次分析还得到一条同源结论：**不得先把定点化的 `A` 相减得到 `A_d`**。它与增益归零同源
—— 都出在定点域对大数量级的抵消。差分展开是「大数相减」，定点化后再相减会把有效位吃掉；
正确做法是在浮点或高精度域构造 `A_d`，或保留精确算子参与差分。落地到本项目：定位链用 `A`
而不用 `A_d`，判据见 `sim/results/x4b_localization_uses_A_not_Ad.md`。
