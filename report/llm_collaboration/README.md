# 大模型协作说明

## 1. 团队的主要贡献

团队确定项目目标、技术路线与验收标准，选择算法移植方案和运行平台；负责实验装置搭建、几何与显示参数确认、现场操作，并根据测试结果作出方案取舍。技术结论和提交材料由团队审核确认。

## 2. AI 的辅助工作

AI 按团队提出的约束，辅助部分代码与校验脚本的实现、报错分析和资料整理，并起草说明文档。团队结合参考结果、工具报告和实验观察，决定哪些建议可以采用。

## 3. 采纳与未采纳的建议

| 建议 | 团队取舍及依据 |
|---|---|
| 移植前核对数据维度、尺度和存储顺序 | 采纳。先明确输入契约，避免格式错误被误认为算法问题。 |
| 用参考输出和独立状态检查共同验证 | 采纳。图像效果之外，还需核对残差、迭代次数和停止条件。 |
| 增加 DSP 以解决访存瓶颈 | 未采纳。该阶段主要受数据搬运限制，单纯增加计算资源不能解决问题。 |
| 将动态循环的 HLS 延迟外推值直接作为性能结论 | 未采纳。团队按明确的输入和计时范围核对结果，区分估算、仿真与板端测量。 |

## 4. 团队总结

AI 能缩短资料梳理和问题排查的时间，方案判断仍依赖团队对系统与实验条件的理解。我们的做法是先明确约束，再检查实现，最后用证据确认结论；每次优化尽量只改变一个因素，保留可比较的输入和结果。

上述经验整理为技能包中的输入契约检查、参考对照、性能分析和故障排查条目，供其他项目复用。历史案例见 [source_notes](source_notes/)。本文依据现有工程和协作摘要整理，经团队审核确认。
